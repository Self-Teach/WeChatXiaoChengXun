# WeChatXiaoChengXun
## 云南茶叶销售小程序开发

【一、总体技术要求】

1. 使用微信小程序原生开发，不使用云开发能力：
   - 不接入云函数、不依赖云数据库；
   - 所有数据（商品信息、茶叶知识、购物车、订单等）均基于本地数据与本地存储实现：
     - 静态基础数据可写在本地 JS 数据文件中（例如 /data/tea.js、/data/knowledge.js 等）；
     - 用户相关数据（购物车、订单、地址信息、登录状态等）通过 wx.setStorageSync / wx.getStorageSync 来模拟本地持久化。
2. 项目采用标准的小程序目录结构（app.js / app.json / app.wxss + 各页面的 *.js/*.json/*.wxml/*.wxss），请检查每个文件的逻辑和引用路径是否正确。
3. 代码中添加清晰、详细的中文注释，特别是：
   - 每个页面、组件的主要功能说明；
   - 关键数据结构字段说明；
   - 重要事件处理函数（如加入购物车、提交订单、切换分类）的逻辑解释；
   - 方便编程小白快速理解代码逻辑和文件之间的关联。

【二、导航栏与页面结构】

整个小程序底部 tabBar 分为 4 个一级页面（页面路径和命名可由你合理设计，但请统一）：

1. 首页：云南茶叶商品主页面（例如：pages/index/index）
   - 展示 8 种云南茶叶商品的列表（后续可扩展）：
     - 每个商品展示：商品缩略图、本地名称、简短介绍、价格等基本信息；
     - 商品列表布局参考主流电商小程序（如两列卡片布局、留白适中、价格突出等）。
   - 每个商品可点击进入“商品详情页面”（例如：pages/product-detail/index）：
     - 商品详情页需要展示内容：
       1）该商品的 3 张本地图片轮播（使用本地 image 资源）；
       2）商品基本介绍（产地、口感、适合人群等）；
       3）商品购买选项（如数量选择、规格选择：如 100g / 200g / 357g 饼等）；
       4）规格型号信息（如熟茶/生茶、年份、仓储等）；
       5）“加入购物车”按钮和“立即购买”按钮；
       6）分享按钮（使用小程序分享能力，配置 onShareAppMessage）；
       7）商品评价区域（可先使用本地静态示例数据，如若无真实数据可展示“暂无评价”）；
       8）商品详情富文本介绍区域（可使用简单文本/分段说明即可）。
   - 首页右侧添加一个“购物车”浮动按钮：
     - 悬浮在页面右下或右中位置；
     - 点击后直接跳转到购物车页面（第三个 tab 对应页面或独立页面）； 
     - 可在按钮上显示购物车内商品数量角标。

2. 茶叶知识科普页面（例如：pages/knowledge/index）
   - 主页面包含几个入口模块：
     1）云南茶分类
     2）云南茶主要产地介绍
     3）云南茶存储事项
     4）云南茶冲泡方法
   - 点击“云南茶分类”后进入分类详情页面（可为子页面，如 pages/knowledge-category/index）：
     - 展示熟茶、生茶、普洱等不同茶类的基本介绍；
     - 每一类内容包括：定义、制作工艺简述、口感特点、适宜人群、简单图文说明。
   - 其他知识模块可以采用分块展示（折叠面板、卡片列表或纯文本分段）：
     - “主要产地介绍”：例如介绍云南不同产区的特点（西双版纳、临沧等）；
     - “存储事项”：如避光、防潮、防异味、通风等注意事项；
     - “冲泡方法”：水温、投茶量、浸泡时间、不同器具的简单说明。
   - 虽然你无法真实联网，但请按“来自权威茶叶知识”的口径组织合理内容，并用注释说明这些内容在真实项目中应从权威资料交叉验证。

3. 购物车页面（例如：pages/cart/index）
   - 展示当前已加入购物车的商品列表：
     - 商品图片、名称、规格、单价、数量、小计价格；
     - 提供数量增减按钮、删除商品功能；
     - 商品选择勾选功能（支持全选/单选）；
     - 底部显示总价和“结算”按钮。
   - 购物车数据要求：
     - 基于本地数据结构 + wx.setStorageSync / wx.getStorageSync 存储；
     - 在加入购物车时，如果同一商品同一规格已存在，应合并数量而不是重复添加多行；
     - 结算时将已选商品生成“订单数据”，写入本地订单列表，并清空已结算商品。

4. 个人中心页面（例如：pages/profile/index）
   - 个人小程序主页整体模块：
     1）登录/头像区域：
        - 提供“登录”按钮（可模拟简单的本地登录逻辑，如输入昵称或使用 wx.getUserProfile 的占位调用方案，用注释说明需要真实授权时的做法）；
     2）订单详情模块入口：
        - 在个人中心页面展示“我的订单”模块，模块中包含 5 个状态入口：  
          - 待付款  
          - 待发货  
          - 待收货  
          - 待评价  
          - 退款/售后  
        - 点击每个状态入口，跳转到订单列表页面（如 pages/order-list/index），并按状态筛选订单；
        - 初始订单数据为空时展示“暂无订单”的占位界面。
     3）地址管理模块：
        - 地址列表页面（如 pages/address-list/index）：展示用户已保存的地址；
        - 支持新增地址、编辑地址、删除地址，字段包括：收货人、手机号、省市区、详细地址等；
        - 地址同样使用本地存储实现。
     4）账号与安全模块：
        - “账号与安全”入口页面（如 pages/account-security/index），包含：
          - 更换手机号（可使用表单输入新手机号，验证格式即可）；
          - 登录密码修改（本地模拟密码存储与校验逻辑，用注释说明真实项目中应后端处理）；
          - 安全中心说明（简单文字介绍账号安全注意事项）。
     5）客服服务模块：
        - 在个人中心中提供“联系客服”入口；
        - 展示内容：例如“添加微信号：SelfLearner 进行咨询”，并可提供一键复制微信号的按钮（使用 wx.setClipboardData）。

【三、图片与图标资源要求】

1. 所有图片和图标以“本地资源”形式调用：
   - 在项目根目录下创建 /images 文件夹（或 /image，但建议 /images）；
   - 商品图片、横幅图、图标等都使用本地图像文件路径（例如 /images/tea1.jpg、/images/icon-cart.png 等）；
   - 你无法真实提供图片文件，但请在代码中事先规划并引用合理的本地路径名称，并用注释说明“实际项目中需将对应图片文件放入 /images 目录”。
2. WXML 中引用图片时使用本地相对路径，确保与项目结构相符；
3. 如需简单图标，可以用文本 + 边框替代，或者预留 icon 路径并附带注释。

【四、UI 风格与配色要求】

1. 整体风格参考主流电商类微信小程序（如京东、天猫系小程序的布局风格），但请做成更符合“云南茶叶”与“中国人审美”的风格：
   - 以较为素雅的配色为主，如米白、浅棕、墨绿等茶系色；
   - 合理使用圆角卡片、分割线、留白，保证阅读体验与操作清晰；
   - 字体大小、行高要适配手机屏幕，避免过密或过疏。
2. 首页可适当设计顶部 Banner（使用本地占位图），展示“云南茶叶”主题；
3. 确保 tabBar 图标和文字清晰，选中状态与未选中状态颜色有明显区分。

【五、数据结构与逻辑说明】

1. 商品数据（以本地 JS 数据文件形式）：
   - 每个商品至少包括字段：id、name、category、price、origin、year、type（熟茶/生茶/普洱等）、desc、specs（可选规格数组）、images（本地图片路径数组）、tags 等；
   - 在代码中用注释说明各字段的含义，方便后续扩展。
2. 茶叶知识数据：
   - 可以写成静态对象或数组，包含模块名称、内容段落、可选图片等；
   - 提供简单的数据结构示例并在注释中解释各字段用途。
3. 购物车数据结构：
   - 每条购物车记录包含：商品 id、名称、规格、数量、单价、小计、勾选状态等；
   - 封装常用操作函数：添加商品、修改数量、切换勾选状态、删除商品、计算总价等，在代码里加详细注释。
4. 订单数据结构：
   - 字段包括：订单 id、商品列表、总金额、创建时间、订单状态（待付款、待发货、待收货、待评价、退款/售后）、收货地址等；
   - 在提交订单时，从购物车选中商品生成订单对象，写入本地存储，并更新购物车数据。
